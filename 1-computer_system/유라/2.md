# 2. 프로세스 관리(기초편)
**ps aux** 명령 : 시스템에 존재하는 모든 프로세스 확인  
--no-header 옵션으로 헤더 출력 제거 가능  
| 필드 | 의미 | 설명 |
|------|------|------|
| `USER` | 소유 사용자 | 해당 프로세스를 실행한 사용자 |
| `PID` | Process ID | 프로세스 고유 번호 |
| `%CPU` | CPU 사용률 | 프로세스가 사용하는 CPU 비율 |
| `%MEM` | 메모리 사용률 | 전체 RAM 대비 점유 비율 |
| `VSZ` | Virtual Size | 가상 메모리 사용량 (KB) |
| `RSS` | Resident Set Size | 실제 물리 메모리 사용량 (KB) |
| `TTY` | 터미널 | 연결된 터미널 (`?`면 없음, 데몬) |
| `STAT` | 상태 | 프로세스의 현재 상태 코드 |
| `START` | 시작 시간 | 프로세스가 시작된 시각 |
| `TIME` | 누적 CPU 시간 | 지금까지 사용한 CPU 총 시간 |
| `COMMAND` | 실행 명령 | 실행된 명령과 인자 전체 |

## 프로세스 생성
### 목적
1. 동일한 프로그램 처리를 여러 프로세스에 나눠서 처리
2. 다른 프로그램 생성  

### 프로세스 생성 방법
**fork()** 함수 : 원본 프로세스인 부모 프로세스가 해당 프로세스의 복사본을 생성. 생성된 프로세스를 자식 프로세스라고 지칭.  
> 절차 : 부모 프로세스가 fork() 함수 호출 > 자식 프로세스용 메모리 영역 확보 후 그 곳에 부모 프로세스의 메모리 복사 > 두 프로세스 모두 fork() 함수에서 복귀  

**execve()** 함수 : 자식 프로세스가 호출하면 자식 프로세스가 새로운 프로그램으로 바뀜.
> 절차 : execve() 함수 호출 > execve() 함수 인수로 지정한 실행 파일에서 프로그램을 읽어서 메모리에 배치하는데 필요한 정보를 가져옴 > 현재 프로세스의 메모리를 새로운 프로세스 데이터로 덮어 씀 > 프로세스를 새로운 프로세스의 최초에 실행할 명령부터 실행  


## 프로세스의 부모 자식 관계
**부팅 시 시스템 초기화 절차**  
1. 컴퓨터 전원 ON
2. BIOS나 UEFI 같은 펌웨어를 기동하고 하드웨어 초기화
3. 펌웨어가 GRUB 같은 부트 로더 기동
4. 부트 로더가 OS 커널 기동
5. 리눅스 커널이 init 프로세스 기동
6. init 프로세스가 자식 프로세스를 기동하고 그 자식 프로세스를 기동하고... 이어져서 프로세스 트리구조 만듦
</br>


## 프로세스 상태
> ps aux 명령 결과의 STAT 필드에서 확인 가능.  

S로 시작 : 이벤트가 발생할 때까지 CPU를 사용하지 않고 가만히 있는 슬립 상태  
R로 시작 : CPU를 사용하고 싶어하는 프로세스로 실행 가능 상태  
실제로 CPU를 사용하는 상태는 실행 상태  
Z로 시작 : 좀비 상태  

## 프로세스 종료
> 프로세스를 종료하려면 exit_group() 시스템 콜 호출


## 좀비 프로세스와 고아 프로세스
**좀비 프로세스**  
- 이미 종료된 프로세스지만, 부모가 종료 상태를 확인하지 않은 상태  
- 부모가 wait()를 호출하지 않아 PID와 종료 정보만 남은 상태  
- 실행 ❌ / 자원 사용 ❌ / PID 점유 ⭕  
- ps에서 Z, <defunct>로 표시  
- 누적되면 새 프로세스 생성 불가 → 시스템 장애  
- 해결: 부모가 wait() 수행 또는 부모 재시작(좀비 자체는 kill 불가)

**고아 프로세스**  
- 부모가 먼저 죽고, 자식이 살아있는 상태  
- 커널이 자동으로 **PID 1(init/systemd)**에게 입양  
- 실행 ⭕ / 정상 프로세스  
- 문제 없음, 리눅스에서 자연스러운 상태  

## 시그널
> 어떤 프로세스가 다른 프로세스에 어떤 신호를 보내서 외부에서 실행 순서를 강제로 변경

kill 명령으로 시그널을 보냄.
| 시그널 | 번호 | `kill` 옵션 | 발생 주체 / 상황 | 기본 동작 | 주요 용도 |
|--------|------|-------------|------------------|-----------|-----------|
| **SIGINT** | 2 | `-INT` | 터미널에서 `Ctrl + C` 입력, 또는 `kill -INT PID` | 프로세스 종료 | 실행 중인 작업을 사용자 의도로 중단 |
| **SIGCHLD** | 17 | `-CHLD` | 자식 프로세스가 종료/중지/재개될 때 커널이 부모에게 전송 | 기본적으로 무시 | 부모가 `wait()` 호출 → 좀비 방지 |
| **SIGTSTP** | 20 | `-TSTP` | 터미널에서 `Ctrl + Z` 입력 | 프로세스 일시 정지 | 포그라운드 작업을 중단하고 잡 제어로 이동 |
| **SIGSTOP** | 19 | `-STOP` | `kill -STOP PID`로 강제 전송 | **즉시 정지 (무시 불가)** | 프로세스 강제 일시정지, 디버깅 |
| **SIGCONT** | 18 | `-CONT` | `kill -CONT PID`, `fg`, `bg` | 중지된 프로세스 재개 | `SIGSTOP`/`SIGTSTP`로 멈춘 작업 재시작 |

## 셀 작업 관리 구현
**작업** : bash 같은 쉘이 백그라운드로 실행한 프로세스를 제어하는 동작 구조  
### 세션
사용자가 gterm 같은 단말 에뮬레이터(terminal emulator) 또는 ssh 등을 사용해서 시스템에 로그인 했을 떄의 로그인 세션에 대응하는 개념. 모든 세션에는 해당 세션을 제어하는 단말이 존재함.
> 세션에는 세션 ID 또는 SID 값이 할당되고, 보통 bash 같은 쉘인 세션 리더 프로세스가 존재함. 세션 관련 정보는 **ps ajx** 명령으로 확인 가능  

### ps ajx 명령 결과 필드
| 필드 | 의미 | 설명 |
|------|------|------|
| `PPID` | Parent PID | 부모 프로세스 ID |
| `PID` | Process ID | 현재 프로세스 ID |
| `PGID` | Process Group ID | 프로세스가 속한 그룹 ID |
| `SID` | Session ID | 세션 ID (보통 로그인 쉘의 PID) |
| `TTY` | 터미널 | 연결된 터미널 (`?`면 없음) |
| `STAT` | 상태 | 프로세스 상태 코드 (`R`, `S`, `T`, `Z` 등) |
| `TIME` | 누적 CPU 시간 | 지금까지 사용한 CPU 총 시간 |
| `COMMAND` | 실행 명령 | 실행된 명령과 인자 |
> 세션에 할당된 단말이 hang up 과 같이 연결이 끊기거나 단말 에뮬레이터 창을 닫으면 세션 리더에 SIGHUP 시그널이 전송됨. 이때 bash는 자신이 관리하던 작업을 종료하고 자신도 종료함.


## 프로세스 그룹
> 세션 내부에 여러개가 존재하며 여러 프로세스를 하나로 묶어서 관리. 셸이 만든 작업이 프로세스 그룹에 해당됨.

- foreground process group : 셸의 포그라운드 작업에 대응. 세션 하나만 존재하고 세션 단말에 직접 접근 가능
- background process group : 셸의 백그라운드 작업에 대응. 백그라운드 프로세스가 단말을 조작하려고 하면 실행이 일시 중단되고, 프로세스가 포그라운드 프로세스 그룹이 될 때까지 상태 유지  


## 데몬
> 상주하는 프로세스로 시스템 시작부터 종료할 때까지 계속해서 존재하며 실행됨.
- 단말의 입출력이 필요 없기 때문에 단말 할당 ❌
- 로그인 세션을 종료해도 영향을 받지 않도록 독자적인 세션을 가짐
- 데몬을 생성한 프로세스가 데몬 종료 어부를 신경 쓸 필요 없이 init 프로세스가 부모가 됨.
